# Cross-Node Thesis Delta Audit

Use this after company longitudinal baselines exist and before a network Thesis Delta or House View is accepted.

## 1. Separate issuers do not automatically confirm independent demand

Several issuers can report stronger revenue, margin, cash or tighter capacity while sharing the same CapEx cycle. Use narrow labels:

- `separate issuer disclosures` — facts reported by different companies;
- `consistent node-level evidence` — bounded variables point in the same direction;
- `independent end-demand confirmation` — reserved for a customer / usage / monetization source that closes the demand-side bridge;
- `cross-company money flow` — unverified unless disclosed transaction, counterparty, contract and materiality evidence exist.

Do not use `independently corroborated` merely because the issuers differ. Preserve the common-cycle confounder.

## 2. Citation closure is semantic, not mechanical

An ID existing in a ledger does not prove it supports the whole sentence. For every material composite claim:

1. split old value, new value, attribution and boundary;
2. require an anchor for each component;
3. keep management attribution separate from reported fact;
4. inspect the cited ID's exact quote / summary / `cannot_prove`, not only its topic label;
5. write every full ID; reject shorthand such as `CLM-X-001/003`.

Typical failure: citing a current-quarter revenue card for a three-quarter change, or a capital card for a commercialization claim.

## 3. Historical fact and thesis extension need different tests

Later customer-side weakness cannot reverse revenue or cash already recognized. Separate:

- **historical realization** — remains factual after verification;
- **persistence test** — normally the next 1–2 reporting cycles, checking revenue / cash against inventory / commitments at the same node;
- **customer-side upgrade test** — same-window capacity activation → usage → revenue / margin / cash bridge;
- **disclosure gap** — missing monetization data returns `UNKNOWN`, never a pass or a negative conclusion.

A falsifier must identify which layer it can reverse. Evidence-quality failure is not a world-state falsifier.

## 4. Constraint stacking needs a stage chain

Management teams listing many constraints does not prove a binding stack. Map the mechanism to observable stages:

```text
silicon-ready → rack-shipped → energized → utilized → monetized
```

Promotion rules:

- `Directional replacement candidate`: separate issuer disclosures show node-level co-occurrence, but no same-project stage sequence exists.
- Strengthen only when one disclosed platform / project shows at least two distinct stage delays and releasing the first does not clear the second.
- Reject the binding-stack mechanism when one dominant stage explains timing and the others show no independent delay.
- Return `UNKNOWN` when stage timestamps, activation or monetization are not disclosed.

Capital pools, currencies, guarantees, customer receipts, government support and purchase commitments remain separate. Multiple nodes committing earlier supports a hypothesis; it does not prove risk transfer or terminal-customer absorption.

## 5. Edge-node choice

Choose the next node by the largest thesis-reversal gap, not by which missing source would make the existing story thicker. Use one discriminating question and predeclare outcomes:

1. bridge strengthened;
2. lag / deterioration;
3. disclosure gap.

Do not allow usage, CapEx or product narrative to substitute for monetization evidence.
